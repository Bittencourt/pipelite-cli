CURRENT (buggy):
```rust
let columns = if args.fields.is_some() {
    let config = deals_table_config();
    config.default_columns.iter().map(|s| s.to_string()).collect()
} else {
    all_columns
};
```

FIXED — swap `is_some()` to `is_none()`:
```rust
let columns = if args.fields.is_none() {
    all_columns
} else {
    let config = deals_table_config();
    config.default_columns.iter().map(|s| s.to_string()).collect()
};
```

This means:
- No --fields flag: columns = all_columns (all 13 fields shown in key-value view)
- With --fields flag: columns = default 6 as fallback, but render_single will use fields as effective_columns anyway

Actually, looking more carefully at render_single: `effective_columns = fields.as_deref().unwrap_or(columns)`. When --fields IS provided, effective_columns = the user's fields list, NOT columns. So the value of `columns` when --fields is present doesn't matter — the output layer ignores it. The bug is that when --fields is ABSENT, columns was set to the 6-column default instead of all_columns.

Simplify the fix: always pass all_columns as the base. Remove the conditional entirely:

```rust
let columns = all_columns;
```

Wait — but the intent was to use the compact default when no --fields is given for the "get" view. Looking at the verification report truth #9, it says "deals get <id> displays as key-value pairs (vertical layout)" showing ALL fields. So the correct behavior for `deals get` with no --fields IS to show all 13 fields. The 6-column default is only for `deals list`.

Therefore the simplest correct fix: just use `all_columns` unconditionally. Delete the conditional block entirely and replace with `let columns = all_columns;`. Also remove the `use crate::api::models::deals_table_config;` import since it's no longer needed.
