  <behavior>
    - CacheStore::new() creates ~/.pipelite/cache/ directory if missing
    - CacheStore::get() returns None for expired entries (TTL exceeded)
    - CacheStore::get() returns Some(data) for valid entries
    - CacheStore::get() returns None (cache miss, not error) for corrupted JSON files
    - CacheStore::set() writes JSON file with embedded timestamp and TTL
    - CacheStore::set() uses atomic write (temp file + rename) to prevent corruption
    - CacheStore::clear() removes all files in cache directory
    - CacheStore::invalidate(key) removes specific cache file
    - CacheStore::invalidate_prefix(prefix) removes all files whose name starts with prefix (for "stages_*" invalidation)
    - TTL constants: pipelines=3600s, stages=3600s, users=7200s, entity_lists=300s
    - Cache keys: "pipelines", "stages", "users", "deals", "orgs", "people", "activities"
    - CacheStore stored as Option<CacheStore> on AppContext (None if cache dir creation fails -- graceful degradation)
    - `pipelite cache clear` removes all cache files and prints confirmation
    - `pipelite cache refresh` fetches all cacheable entities via API and stores them (uses auto-paginate pattern to get all records)
    - Cache refresh respects --quiet flag
  </behavior>

       - `get<T: DeserializeOwned>(key)`: read file, parse CacheEntry, check is_expired(). On any error (IO, JSON parse), delete corrupted file and return None.
       - `set<T: Serialize>(key, data, ttl_seconds)`: write to temp file in cache_dir, then fs::rename for atomicity.
       - `clear()`: remove_dir_all + create_dir_all.
       - `invalidate(key)`: remove_file, ignore errors.
       - `invalidate_prefix(prefix)`: read cache directory, remove all files whose stem starts with prefix. Ignore errors. This is needed by Plan 04 for "stages_*" invalidation when a pipeline changes.
       - TTL constants: `TTL_PIPELINES=3600`, `TTL_STAGES=3600`, `TTL_USERS=7200`, `TTL_ENTITY_LIST=300`.
       - Key constants: `KEY_PIPELINES="pipelines"`, `KEY_STAGES="stages"`, `KEY_USERS="users"`, `KEY_DEALS="deals"`, `KEY_ORGS="orgs"`, `KEY_PEOPLE="people"`, `KEY_ACTIVITIES="activities"`.
