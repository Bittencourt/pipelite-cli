**CONTEXT AMENDMENTS applied (orchestrator, fact-driven from research — binding):**
1. **`--description` DROPPED** from create (amends the original CONTEXT create-input decision): the server has no description field anywhere — DB schema + both zod schemas contain only `{url, events, active}` and silently strip unknown keys. cli/webhooks.rs must not contain the word "description" (grep-pinned). `--stdin` remains the full-control escape hatch.
2. **https enforced client-side**: create/update `--url` must start with `https://` or exit 2 pre-HTTP with a hint (mirrors the server's create/update zod rule; the server 422s, the CLI exits 2 before any request).
3. **Foreign webhook 403 even for admins** (unlike trash/audit admin powers) — hint already registered; this plan only verifies it with a stub probe.

**Planner decisions pinned (agent's-discretion areas):**
- **Show-once mechanism per format**: table/plain/csv → render the create response WITHOUT the secret in the payload, then warning + secret on their own stdout lines (exactly once, truncation-proof). json → render the full server body (secret inside the pretty-printed JSON, exactly once, on its own line) and print ONLY the warning line to STDERR so `| jq` keeps working. Quiet never suppresses the warning/secret lines — they ARE the output.
- **`(shown once at creation)` placeholder** renders as the `secret` display value in list/get in ALL formats including --json (a synthetic display key, value is self-documenting; CONTEXT locks this text into list/get output — deliberate deviation from wire-exactness).
- **`--stdin` on create/update is validated too**: if the raw JSON has a `url` key it must be https://; if it has `events` every entry must be in the 13. Full control does not include creating dead webhooks the server will silently never fire.
- **Update flag validation precedes the GET** (bad --events/--url → exit 2, counter == 0, no fetch).
- **`--dry-run` on update previews with ZERO HTTP** (CLAUDE.md global contract): it renders the provided delta as a PUT preview with a note that omitted keys are preserved. The EXECUTION path does the real get→merge→PUT.
- **Cache write happens ONLY in list.rs**, from the list response (never contains the secret — P7). No ArgValueCandidates wiring this phase (WHOK-04 completions deferred).
- **Delete is single-ID only** (templates single_delete contract). Multi-ID batch delete is not in any Phase 11 requirement.
