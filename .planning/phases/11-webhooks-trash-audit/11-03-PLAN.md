**Planner decisions pinned (agent's-discretion areas):**
- **Command shape**: `pipelite audit list [filters]` — a group with one subcommand (consistent with webhooks/trash; leaves room for future viewers). CONTEXT calls audit a "viewer"; the orchestrator's plan spec says "`audit` group — list".
- **No --all** (locked): the server has no trash-style low offset cap, only the global 1e6 clamp — not a practical bound. after_help states "pages capped at 100 — iterate --offset" (notes precedent).
- **Limit clamp client-side**: `--limit` clamped into 1..=100 before the request (matches parsePagination; the security domain pins the client-side clamp). `--limit 0` → 1, `--limit 150` → 100 on the wire.
- **No client-side enum validation**: filter values pass through verbatim; the server 422s invalid enums and the Phase 8 parser renders the message (Architectural Responsibility Map: audit filter validation = API server tier).

- **Empty list**: stderr "No audit entries" + filters pointer, quiet-suppressed, exit 0 (consistency with notes/webhooks/trash lists).
- **No cache** for audit (never cached per CONTEXT).
