Key patterns:
- `cmd().write_stdin(json_string)` to pipe data
- `.arg("--dry-run")` to avoid HTTP calls
- `.assert().success().stdout(predicate::str::contains(...))` for output checks
- `.assert().failure()` for error cases
- Non-TTY context (piped stdin) means `no_input` is true, format defaults to JSON

**IMPORTANT note about write_stdin(""):**
`write_stdin("")` creates a piped (non-TTY) stdin with empty content. This means:
- `io::stdin().is_terminal()` returns `false` (stdin is a pipe, not a TTY)
- The process receives an empty stdin stream, not a TTY with no input
- This is useful for testing non-TTY behavior without providing actual JSON data
