    For every create/update/delete command handler across all 6 entities (deals, orgs, people, activities, pipelines, stages):

    After the successful API call (after the response is received and before output rendering), add cache invalidation:
    ```rust
    if let Some(ref cache) = ctx.cache {
        cache.invalidate("entity_key");
    }
    ```

    Entity key mapping:
    - deals create/update/delete -> invalidate KEY_DEALS
    - orgs create/update/delete -> invalidate KEY_ORGS
    - people create/update/delete -> invalidate KEY_PEOPLE
    - activities create/update/delete -> invalidate KEY_ACTIVITIES
    - pipelines create/update/delete -> invalidate KEY_PIPELINES. Also invalidate all stages caches by calling cache.invalidate_prefix("stages_") since pipeline changes may affect stage relationships.
    - stages create/update/delete -> invalidate KEY_STAGES and the parent pipeline's stage cache "stages_{pipeline_id}". The pipeline_id is available from the command args or the stage response.

    Also add invalidation to `--stdin` batch create handlers for deals/orgs/people: after batch create succeeds, invalidate the entity cache.

    Import KEY constants from `crate::cache`.

    This is a mechanical, repetitive change across 18 files. Each file gets 2-4 lines added after the API success path. No behavioral changes to existing logic.
