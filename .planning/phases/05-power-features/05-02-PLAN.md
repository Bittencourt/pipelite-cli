       - For JSON format: build a single JSON array with pipeline objects containing name, id, total_deals, total_value, and stages array with name, deals, value per stage. Print with serde_json::to_string_pretty.
       - For CSV/plain format: flatten all pipelines' stage rows with an extra "pipeline" column.
       - If no pipelines found, print "No pipelines found." and return Ok(()).

<task type="auto">
  <name>Task 2: ASCII art splash screen on TTY with no subcommand</name>
  <files>src/splash.rs, src/main.rs, src/cli/mod.rs, tests/splash_test.rs</files>
  <action>
    1. Create `src/splash.rs`:
       - Define `LOGO` as a hardcoded `&str` constant with bold block-letter ASCII art spelling "PIPELITE" (figlet-style chunky font). Use a visually appealing design like:
         ```
          ____  _            _ _ _
         |  _ \(_)_ __   ___| (_) |_ ___
         | |_) | | '_ \ / _ \ | | __/ _ \
         |  __/| | |_) |  __/ | | ||  __/
         |_|   |_| .__/ \___|_|_|\__\___|
                 |_|
         ```
       - `pub fn print_splash(configured: bool, color: bool)`:
         - If `color`: print LOGO using `.cyan().bold()` from the colored crate.
         - Else: print LOGO plain.
         - If `configured` (has API key):
           ```
             Try:  pipelite deals list
                   pipelite dashboard
                   pipelite --help
           ```
         - If not configured:
           ```
             Get started: pipelite init
           ```
         - Print hints in default terminal color (no accent color).

    2. Update `src/main.rs`:
       - Before `Cli::parse()`, check `std::env::args().len() == 1 && std::io::stdout().is_terminal()`.
       - If true: load config via `load_config(None).ok()`, determine `configured` (config exists and api_key is non-empty), determine `color` (check NO_COLOR env var and --no-color is not in args -- but since we haven't parsed args yet, just check NO_COLOR env var), call `print_splash(configured, color)`, and return early (exit 0).
       - If false (non-TTY or has subcommand): proceed with normal `Cli::parse()`.
       - This approach avoids making `Commands` optional. The splash intercepts before clap ever runs.
       - Add `mod splash;` to main.rs module declarations.

    3. Handle edge case: if user runs `pipelite --no-color` with no subcommand, clap will error because Commands is required. Since the splash intercept checks `args.len() == 1`, passing `--no-color` means args.len() == 2, so clap runs and errors with "requires subcommand". This is acceptable -- `--no-color` alone is not a valid invocation. The NO_COLOR env var is the proper way to suppress color on splash.

    4. Create `tests/splash_test.rs`:
       - Test: running `pipelite` with no args in non-TTY (piped, which is what assert_cmd does) shows clap help text (contains "Usage:" or "Manage your Pipelite CRM"), NOT the splash screen. This proves non-TTY skips splash.
       - Test: `pipelite --help` still shows normal help text.
  </action>

  </verify>
