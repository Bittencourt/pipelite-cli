  <name>Task 1: HTTP client and AppContext</name>
  <files>src/api/mod.rs, src/api/models.rs, src/context.rs</files>
  <action>
1. Create `src/api/models.rs`:
   - Define `PingResponse` struct with `status: String` (and any other fields the server might return). Derive `Deserialize`.

2. Implement `src/api/mod.rs` -- the `PipeliteClient`:
   - `PipeliteClient` struct holds: `client: reqwest::Client`, `base_url: String`, `api_key: String`.
   - `PipeliteClient::new(config: &AppConfig) -> Result<Self>`: build reqwest Client with `connect_timeout(Duration::from_secs(5))`, `timeout(Duration::from_secs(30))`, default headers (Authorization: Bearer {api_key}, Accept: application/json, User-Agent: pipelite/{version}). Store base_url and api_key.
   - `PipeliteClient::from_credentials(url: &str, key: &str) -> Result<Self>`: same as new but takes raw url and key (used by init before config exists).
   - `pub async fn ping(&self) -> Result<String>`: GET `{base_url}/api/v1/ping` (or similar health endpoint). Return status string. On HTTP errors, map to `CliError::Connection` with actionable hint. On auth errors (401/403), map to `CliError::Auth` with hint about checking API key.
   - All HTTP logic goes through PipeliteClient. Commands never touch reqwest directly.

3. Implement `src/context.rs` -- the `AppContext`:
   - `AppContext` struct: `config: AppConfig`, `client: PipeliteClient`, `output_format: OutputFormat`, `quiet: bool`, `verbose: bool`, `color: bool`.
   - `AppContext::build(cli: &Cli) -> Result<Self>`: load config via `load_config(None)`, create PipeliteClient from config, detect output format (cli.format or TTY auto-detect), determine color (not cli.no_color AND stdout is TTY AND NO_COLOR env not set).
   - This is the single source of truth passed to all command handlers.

4. Update `src/main.rs` to use real AppContext::build for Ping and Config commands. Init remains special (no config needed yet). Wire error handling: catch errors, call display_error, exit with exit_code.

<task type="auto">
  <name>Task 2: Init wizard, ping command, and config commands</name>
  <files>src/commands/init.rs, src/commands/ping.rs, src/commands/config.rs, src/commands/mod.rs, src/output/table.rs</files>
  <action>
1. Implement `src/commands/init.rs`:
   - `pub async fn run(args: &InitArgs, quiet: bool) -> Result<()>`
   - If both `args.url` and `args.key` are Some: headless mode, use provided values directly.
   - Otherwise: interactive wizard using dialoguer (sync, before async):
     a. `dialoguer::Input` for server URL with default "https://app.pipelite.io"
     b. `dialoguer::Password` for API key (masks input)
   - After getting URL and key:
     a. Print "Testing connection..." to stderr (unless quiet)
     b. Create `PipeliteClient::from_credentials(&url, &key)` and call `.ping().await`
     c. On success: print "Connected successfully!" to stderr (unless quiet)
     d. On failure: return error with hint about checking URL and API key
   - Build `AppConfig::new(url, key)` (add this constructor to config.rs if needed)
   - Call `write_config(&config_path()?, &config)` to save
   - Print "Configuration saved to {path}" to stderr (unless quiet)
   - Handle case where config already exists: use `dialoguer::Confirm` to ask "Configuration already exists. Overwrite?" (in interactive mode) or overwrite silently in headless mode.

2. Implement `src/commands/ping.rs`:
   - `pub async fn run(ctx: &AppContext) -> Result<()>`
   - If not quiet AND stderr is TTY: create indicatif spinner on stderr with "Connecting..." message, steady tick at 80ms.
   - Measure latency with `Instant::now()` around `ctx.client.ping().await`.
   - Clear spinner on completion.
   - If not quiet: print to stderr: "Server: {url}", "Status: {status}", "Latency: {ms}ms".
   - On error: spinner cleared, error propagated with Connection variant and hint.

3. Implement `src/commands/config.rs`:
   - `pub fn run(ctx: &AppContext, cmd: &ConfigCommands) -> Result<()>`
   - `ConfigCommands::Show`: load config, display as a formatted table using comfy-table. Mask the API key (show first 8 chars + "..."). Write table to stdout. If format is JSON, serialize config as JSON to stdout instead.
   - `ConfigCommands::Set { key, value }`: call `set_config_value(&config_path()?, key, value)?`. Print confirmation to stderr (unless quiet): "Set {key} = {value}".
   - `ConfigCommands::Get { key }`: load config, parse dotted key, print just the value to stdout. Error if key not found with hint showing valid keys.

4. Create `src/output/table.rs`:
   - Helper function to create a comfy-table Table for config display.
   - Two columns: Key, Value. Add rows for each config field with section prefixes (server.url, server.api_key, output.format, display.no_color).

5. Update `src/commands/mod.rs` to export all command modules.

6. Update `src/main.rs` to pass `quiet` flag to init command and wire all real command handlers.
