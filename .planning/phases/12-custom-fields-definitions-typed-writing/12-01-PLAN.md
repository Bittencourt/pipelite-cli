**CONTEXT AMENDMENTS applied (orchestrator, fact-driven from research — binding):**
1. **`--description` DROPPED** from create: the server has no description field anywhere on the model, serializer, or either zod schema. cli/custom_fields.rs must not contain the word "description" (grep-pinned); the create body never carries a description key.
2. **NO `--position` on create**: the POST schema has no position field (zod strips it) and the server auto-assigns max+10000. `--position` exists on UPDATE only (`Option<f64>` — PUT is the only writable path).
3. **NO `deleted` column / tombstone marker**: the list route deliberately includes soft-deleted rows but the serializer omits `deleted_at` — indistinguishable, so CONTEXT's "deleted column" decision is unimplementable. Instead: list help AND delete help carry the note "deleted definitions remain in list output; the server does not mark them". Re-delete → 404 follows the standard NotFound path (no special casing).
4. **`--type` accepts `select` AND `single_select`** — `select` normalizes to the wire enum `single_select` (server has only `single_select`); all other tokens pass through verbatim; unknown tokens exit 2 pre-HTTP. multi_select config shape = `{"options": string[]}`.
5. **The server validates NOTHING on the v1 path** (validateFieldValues is UI-only) — every enum/config check in this group is client-side, pre-HTTP, exit 2, mirroring the webhooks 13-event precedent.

**Planner decisions pinned (agent's-discretion areas):**
- **`--entity-type` normalization**: 9 aliases → 4 server tokens, trash-precedent match: deal/deals→deal, organization/organizations/orgs→organization, person/people→person, activity/activities→activity. Plain-String arg (NOT ValueEnum — the exit-2 hint must fire, same reasoning as trash). The normalized SERVER token goes on the wire and into the list column.

Accepted set: text, number, boolean, date, select, single_select, multi_select, file, url, lookup, formula.
- **`--options` strictness**: required for select/single_select/multi_select (an options-less select definition renders an empty dropdown — the CLI refuses, exit 2, mirroring webhooks' required --events); rejected on every other type (exit 2 — a silently-ignored flag is the exact dead-value bug class this milestone removes). Empty segments in the comma-list are skipped.
- **Create flag path always sends `required` and `show_in_list`** (booleans defaulting false, matching the server's `required || false` materialization) — deterministic body shape, wire-test pinned.

- **No `--all` on list** (webhooks/audit precedent): definitions per entity are small; help notes "page cap 100 — iterate --offset".
